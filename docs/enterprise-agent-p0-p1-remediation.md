## 2. 状态定义

| 状态 | 含义 | 使用条件 |
| --- | --- | --- |
| 待开始 | 尚未进入实施 | 已完成范围识别，但没有代码或设计变更 |
| 进行中 | 正在设计、开发或验证 | 已有负责人开始实施，尚未满足全部验收标准 |
| 阻塞 | 当前无法继续 | 必须记录阻塞原因、依赖方和解除条件 |
| 已完成 | 已满足完成定义 | 代码、迁移、测试、文档和风险记录均已完成 |
| 暂缓 | 经评审后推迟 | 必须记录决策原因和重新评估条件 |

### 2.1 状态更新规则

1. 开始处理某项前，将其“实施状态”改为“进行中”，并在“实施记录”追加一条记录。
2. 实施过程中若缺少外部系统、业务规则或安全决策，将状态改为“阻塞”，明确阻塞方与解除条件。
3. 只有该项全部验收标准满足后才能标记为“已完成”；部分完成仍保持“进行中”。
4. 每次状态变化必须更新“最后更新”日期，并在文末保留实施记录，不覆盖历史记录。
5. 单项实施产生的数据库迁移、配置变化、验证命令和遗留风险，应写入该项的完成记录。
6. 若实施范围发生变化，先更新本文并记录原因，再修改代码。

### 2.2 完成定义

- 代码已进入当前工作区，且没有绕过认证、授权、审计或组织隔离。
- 数据结构变化通过 Alembic 增量迁移完成，并验证升级路径。
- 核心正常路径、拒绝路径和跨组织隔离路径有自动化测试。
- `pytest`、Ruff、mypy 以及受影响组件的专项验证通过。
- 新增配置已加入配置模型、示例配置和运维文档，敏感值未进入代码库。
- 管理操作、策略变更和高风险执行具备审计记录。
- 已记录兼容性、部署顺序、回滚方式和仍然存在的风险。

## 4. 共同实施约束

1. **组织隔离**：新增资源必须绑定组织，查询和写入必须显式带组织边界，禁止仅凭资源 ID 跨组织访问。
2. **服务端授权**：前端权限不能替代后端 RBAC；管理、发布、审批、导出和策略变更必须在 API 层校验。
3. **增量迁移**：数据库结构仅通过 Alembic 前向迁移变更，不重写已发布迁移。
4. **安全默认值**：新增高风险能力默认关闭或只读；超时、限额、网络出口和工具权限采用拒绝优先策略。
5. **敏感信息保护**：密钥、Token、密码、Cookie、证书和连接串不得进入数据库明文字段、Prompt、Trace、日志或评测样本。
6. **审计可追溯**：管理操作、策略变更、发布、回滚、审批、数据导出和删除操作必须记录操作者、组织、对象、结果和 Trace ID。
7. **严格契约**：新增 API 请求模型保持 `extra="forbid"`，响应结构应版本化并避免返回内部异常或敏感数据。
8. **测试随风险扩展**：核心逻辑覆盖成功、拒绝、幂等、并发和组织隔离；队列与生命周期任务覆盖重试和恢复。
9. **兼容现有模式**：优先复用当前 FastAPI、SQLAlchemy、Alembic、OIDC、RBAC、审计、Vault 和可观测性实现。
10. **可回滚部署**：数据库和异步任务变更必须说明部署顺序，并保证滚动部署窗口内的兼容性。

## 5. P0 整改项

### P0-01 Web 工作台和管理控制台

**实施状态：待开始**

**最后更新：2026-09-15**

**目标**

优先为普通用户提供可以直接完成业务查询的 Web 入口，再按真实使用需要增加管理和治理页面，不再等待全部后台能力稳定后才建设前端。

**当前情况**

- 仓库当前以 FastAPI 后端、CLI、OpenAPI 和运维文档为主，没有前端工程。
- 后端已有 OIDC、组织、RBAC、会话、运行、审计和配额基础，可作为工作台的权限与数据来源。

**实施范围**

- U1：Vue 3 + TypeScript 工程、登录、会话恢复、基础布局和统一 API 错误处理。
- U2：对话列表、消息流式展示、运行状态、停止生成和刷新恢复。
- U3：PermissionSystem 连接、断开、授权状态和聊天内连接引导。
- U4：历史对话、引用来源、部分结果说明和轻量反馈。
- U5：默认 Agent 的基本信息、系统提示词、Tool、草稿、版本、发布和回滚。
- 前后端契约：类型安全客户端、统一错误模型、分页、并发冲突和权限拒绝处理。
- 安全前端基线：复用服务端 OIDC Session，落实 CSRF/XSS 防护，禁止浏览器持久化敏感 Token。
- 审批中心、成员与角色管理、配额看板、数据治理和安全策略中心明确延后。

**验收标准**

- 普通用户可完成登录、发起对话、查看流式结果、取消运行、查看引用并提交反馈。
- 用户可以连接自己的 PermissionSystem 账号，并完成至少一个真实只读查询。
- 页面刷新或短暂断网后可以恢复会话和最终运行状态。
- Agent 管理员可创建草稿、版本并执行发布和回滚；强制评测门禁不作为首版前置条件。
- 登录、连接、对话、取消、引用和反馈具备端到端冒烟测试，桌面端不存在阻断操作的布局问题。

**主要风险或阻塞信息**

- 默认采用 Vue 3 + TypeScript 独立前端工程；企业统一门户集成方式可在内部试用后确认。
- 本项不再依赖 P0-02、P0-03 全部完成；仅在具体页面被阻塞时补充最小 API。

### P0-02 Agent 发布控制面

**实施状态：进行中**

**最后更新：2026-09-15**

**目标**

将当前全局模型和 `system_prompt` 配置升级为按组织管理的 Agent 定义、不可变版本和可审计发布流程，避免通过修改环境变量直接改变生产行为。

**当前情况**

- 第三批 3A 已提供组织级 Agent、草稿乐观锁、不可变版本、开发环境发布/回滚和 Run 精确版本绑定。
- 开发环境 EvalOps 门禁已在第三批 3B 接入；当前仍缺 Agent 停用流程、生产门禁切换及默认 Agent 数据迁移，因此生产继续使用全局 `legacy` 配置。
- 当前优先复用已有接口建设 U5 最小管理页面；停用流程、生产强制门禁和全量迁移继续保留在后续治理阶段。

**实施范围**

- 新增 Agent、Agent Version、Deployment/Release 等持久化实体并绑定组织。
- 版本快照包含提示词、模型引用、允许工具、运行限制、引用策略和安全策略引用。
- 草稿支持乐观并发控制；已发布版本不可原地修改，只能创建新版本。
- 提供创建、校验、版本化、发布、停用和回滚 API，并实施细粒度 RBAC。
- 发布动作接入 P0-03 评测门禁；紧急绕过需要独立权限、原因和审计记录。
- Run 固化实际使用的 Agent Version ID 和配置摘要，保证历史可重放、可解释。
- 明确旧全局配置迁移到默认 Agent 的兼容策略和部署顺序。

**验收标准**

- 不同组织可以维护同名 Agent 且互不可见。
- 发布版本不可变，运行记录可定位到精确版本，回滚不会修改历史运行。
- 未通过门禁、无权限或版本冲突的发布请求被明确拒绝并审计。
- 发布和回滚具备幂等语义，重复请求不会产生不一致部署状态。
- 迁移后现有调用方在兼容窗口内仍可运行，并有明确弃用路径。

**主要风险或阻塞信息**

- 需要先确定 Agent 配置的最小稳定 Schema，以及环境是全局、按组织还是按租户自定义。
- 模型凭证仍应由 Vault 或环境引用，不进入版本快照。

### P0-03 EvalOps 评测与发布门禁

**实施状态：暂缓**

**最后更新：2026-09-15**

**目标**

建立版本化评测数据集、可重复评测运行、质量指标和发布门禁，防止提示词、模型或工具策略变更未经量化验证直接上线。

**当前情况**

- 第三批 3B 已提供组织级评测数据集、不可变版本、评测运行、确定性结果和开发环境发布门禁。
- 当前仍缺基线对比、独立 Eval Worker、结果导出和生产门禁切换。
- 为优先交付 U1-U6，现有开发环境能力保持可用，但本项不再作为内部试用前置条件；生产保持 `off` 或 `advisory`。

**实施范围**

- 建立评测数据集、数据集版本、用例、评测运行、单例结果和指标汇总模型。
- 支持答案质量、工具选择、参数正确性、引用完整性、安全拒答、延迟和成本指标。
- 对非确定性任务支持规则、结构化断言、模型裁判和人工复核，并记录裁判版本。
- 保存被测 Agent Version、模型参数、数据集版本和执行环境，保证结果可追溯。
- 定义绝对阈值、相对基线回归阈值和硬性安全失败项，接入 P0-02 发布流程。
- 评测样本进入前执行敏感数据治理，限制原始生产会话直接成为评测数据。
- 提供评测触发、查询、取消和结果导出 API；长任务通过 P0-05 执行。

**验收标准**

- 相同版本和数据集可重复运行，结果包含逐用例证据与汇总指标。
- 门禁可阻止质量回归或安全失败版本发布，并记录具体失败项。
- 阈值和数据集变更经过版本化与审计，不能静默影响既有结果。
- 裁判 Prompt、模型和解析失败均可追踪，人工复核不会覆盖原始机器结果。
- 至少建立一套覆盖核心业务、安全拒答和越权工具调用的回归集。

**主要风险或阻塞信息**

- 需要业务 Owner 确认代表性样本、可接受阈值和人工复核责任人。
- 模型裁判只能作为证据之一，不能替代硬性权限和安全断言。

### P0-04 用户反馈和事件闭环

**实施状态：待开始**

**最后更新：2026-09-15**

**目标**

先让用户能够对实际回答提交简单、可追溯的反馈，为可用性改进提供输入；事件处置和评测集扩充在反馈数据形成规模后再建设。

**当前情况**

- `docs/ai-agent-implementation-plan.md` 规划了 `POST /api/v1/runs/{id}/feedback`。
- 当前 `src/ai_agent/conversations/api.py` 未实现反馈接口，也缺少事件分派和处置状态。

**实施范围**

- 新增运行反馈：赞/踩、分类、可选说明、目标消息或运行，并限制用户只能反馈可访问资源。
- 支持幂等提交和用户修改反馈，保留必要审计历史，防止重复计数。
- 提供用户反馈提交和组织管理员基础查询 API，并在 U4 中接入工作台。
- 首期不建设 Issue/Incident、负责人、SLA、自动工单和反馈转评测数据集。
- 后续如需将生产案例提升为评测用例，必须另行实现授权、脱敏、审核和数据集版本化。

**验收标准**

- 用户只能对本组织且本人可访问的运行提交反馈，重复请求不产生重复记录。

**验收标准**

- 每次运行可解释主要成本组成，并能聚合到组织与 Agent 版本。
- 价格变更不篡改历史原始用量，估算与账单差异有对账机制。
- 达到硬限制时新运行被一致拒绝，已有运行按明确策略完成或终止。
- 预算规则和豁免变更经过权限校验与审计。

**主要风险或阻塞信息**

- 提供方账单通常延迟且计费口径不同，平台成本应明确标记为估算或已对账。

### P1-06 SIEM 外送和外部不可变审计

**实施状态：暂缓**

**最后更新：2026-09-15**

**目标**

将关键身份、安全、管理和执行事件可靠外送到企业 SIEM 或不可变存储，降低仅依赖应用数据库审计被篡改或丢失的风险。

**当前情况**

- 已有应用内审计记录和安全事件基础。
- 缺少标准化外送、传输确认、积压恢复、完整性校验和外部保留策略。

**实施范围**

- 定义版本化审计事件信封，包含事件 ID、时间、组织、主体、动作、对象、结果、风险和 Trace ID。
- 通过事务 Outbox 或等价机制保证业务变更与待外送事件一致，不在请求事务内直接依赖 SIEM。
- 支持带签名或完整性链的批量外送、重试、游标、死信和受控重放。
- 连接配置与凭证使用 Vault，网络出口采用 allowlist、TLS 和超时限制。
- 对外送延迟、积压、失败、签名异常和消费确认建立指标与告警。
- 定义外部不可变存储保留期、访问审批和灾难恢复验证。

**验收标准**

- SIEM 暂时不可用时业务操作可按策略继续，事件不丢失且恢复后按序或可去重外送。
- 重试与重放不会在接收端形成不可识别的重复事件。
- 外送内容不包含密钥、Token、完整 Prompt 或未经批准的敏感数据。
- 可通过完整性信息发现审计事件删除、替换或链断裂。

**主要风险或阻塞信息**

- 需确认目标 SIEM 协议、事件规范、吞吐限制、数据驻留和不可变存储责任边界。

### P1-07 MCP 协议合规回归套件

**实施状态：暂缓**

**最后更新：2026-09-15**

**目标**

将现有 MCP 探针升级为可在 CI 和供应商接入流程中重复执行的协议、安全与兼容性测试套件。

**当前情况**

- 已实现 MCP Streamable HTTP 的初始化、工具发现和受控只读调用探针。
- 现有验证更偏环境联调，尚未形成服务端接入认证与持续回归矩阵。

**实施范围**

- 覆盖 initialize、能力协商、工具列表、Schema、调用、取消、超时、错误和连接关闭。
- 验证 OAuth 资源指示、受众、Scope、Token 过期、权限拒绝和凭证不泄露。
- 增加畸形消息、超大响应、重定向、非允许网络目标、未知字段和协议版本不兼容测试。
- 建立模拟 MCP Server 与契约夹具，真实供应商测试通过显式配置运行，CI 不依赖外部不稳定服务。
- 输出机器可读报告，记录客户端/服务端版本、失败阶段和敏感信息脱敏结果。
- 将关键兼容性用例接入依赖升级和发布门禁。

**验收标准**

- 支持的 MCP Server 必须通过固定版本的协议、安全和业务 Tool 契约测试。
- 客户端或 SDK 升级时可发现协议、Schema、错误处理和认证回归。
- 测试日志、报告和失败快照不包含访问 Token 或业务敏感返回。
- 外部服务不可用不会导致本地确定性契约测试失效。

**主要风险或阻塞信息**

- 需维护支持的 MCP 协议与 SDK 版本矩阵，并与服务提供方约定兼容窗口。

## 9. 当前不纳入范围

以下能力不是当前 U1-U6 的默认实施内容。如后续业务需要，应另行评审，不能隐含加入当前里程碑：

- 通用多 Agent 自主协作、群体规划或无限递归委派。
- 未经人工审批的高风险写操作、资金操作、权限变更或外部发布。
- 与具体企业知识源和授权模型无关的通用 RAG 平台。
- 新建通用工作流 DSL、低代码编排平台或插件市场。
- 为追求基础设施一致性而进行 Kubernetes、Service Mesh 或全量微服务重构。
- 使用模型检测替代确定性的身份、权限、Schema、网络和审计控制。
- U1-U6 期间新增独立 Eval Worker、生产强制门禁、SCIM、SIEM、多模型路由、长期记忆或完整 FinOps。
- 首版审批中心、组织治理控制台、复杂运行诊断台和安全策略运营台。
